## 10. 代码自查说明（渲染/采样专项，2026-10-25，T-047 观察轮）

> 背景：用户三轮反馈——①背景采样"超出了框本身的范围，去到了别的屏幕的内容"；
> ②"选中框移动走之后会有一个拖影，并且消失会有延迟"；③背景采样导致界面卡顿，
> 并提问"是不是因为没有把代码模块化构建的问题"、"可以用 CPU/GPU 计算吗、难不难、
> 或不用计算能否优化"。本轮**零产品代码改动**，实机取证 + 全量代码自查后落此文档；
> 修复清单见 §10.4（下一轮 T-049 执行）。

### 10.2 三现象根因（全部定位，均有证据）

1. **采样越界到别的屏幕**：`backdrop._tick` 的坐标换算用
   `geo - screen.geometry()`（**screen-local**），而 GDI BitBlt 的
   `GetDC(NULL)` 坐标系是**全局虚拟屏**（主屏原点）。副屏上偏移 =
   (2560, 172)：Dock 在全局 (-1879, 805)，产品实际采样了主屏的
   (681, 977)——即"别的屏幕的内容"（证据 B 墙纸 vs 证据 C 聊天窗口）。
   主屏上 sg.x()=0，两套坐标重合——所以此前主屏测试未暴露。
2. **拖影 + 延迟消失（自反馈回路）**：GDI **会采集非分层的 Dock 窗口自身**
   （证据 C：Dock 与键帽完整出现在 GDI 捕获中）→ 采样图里含有 Dock 上一帧
   （含选中高亮）→ 玻璃把"200ms 前的自己"画进当前帧 → 选中框移动后旧高亮
   以残影形式残留 1~2 个刷新周期（200ms/次）后随采样更新消失——与用户描述
   完全一致。**D-042 spike 的误判教训**：spike 测试窗调用了
   `setWindowOpacity(0.999)` 被强制为分层窗口（GDI 排除分层窗）而得出
   "GDI 排除自身"的结论；真实 Dock 的 windowOpacity == 1.0，非分层 → 被
   采集。spike 与真实窗口的分层状态不一致 = 结论失效。
3. **卡顿**：直接根因是**主线程阻塞**（D-044 已修——grabWindow 整屏回读
   改后台线程 GDI 区域拷贝，实测采样运行中主线程单帧 9.6ms），非本轮新增；
   用户本轮的"卡"感 = 现象 1/2 的观感（采错内容 + 残影跳变）+ 历史版本印象。

### 10.3 模块化自查（回答"是不是没把代码模块化构建的问题"）

**结论：文件级模块化基本清晰，卡顿与三现象的直接根因是执行层缺陷而非文件
组织；但 `dock_strip.py` 单类职责过重是真实的模块化债，它放大了回归风险
（D-043/D-046 两轮 paintEvent 内变量作用域错误都发生在这个文件）并使效果
调参互相纠缠。**

- **清晰的部分**：core（状态机/模型，纯逻辑零 UI 依赖）｜ui（窗口/绘制）｜
  io_sink（键盘模拟）｜debug（面板/工具）分层成立；采样器独立为
  `ui/backdrop.py`（线程封装完整）；事件与配置有独立模块。
- **债务清单（按危害排序）**：
  1. `dock_strip.py`（~700 行）单类五职责：鱼眼布局计算、玻璃质感绘制、
     光效绘制、背景折射合成、鼠标语义——paintEvent 内多分支嵌套，改一处
     光效可能碰坏布局（D-043/D-046 两次 NameError 均在此文件的作用域错位）；
  2. 效果参数散落：MAXS/SPREAD/S_CAP 常量、Texture 五字段、Skin 字段、
     及大量硬编码 alpha/半径数字（52/34/12/70/46/2.2U/6.2px…）无集中管理，
     "羽化/减量"类调整需要全文搜索；
  3. 无渲染性能基准：帧耗时度量只在 harness 临时脚本里，未纳入常规巡检；
  4. `candidate_window.py` 混合窗口管理 + 光源轮询 + 采样分发 + 设置回调。
- **CPU/GPU 评估（答复用户）**：当前规模（~1385×118 区域、200ms 节奏）
  后台 CPU 线程 1~3ms 已足够，无需 GPU；GPU 路线（DXGI Desktop
  Duplication + shader 透镜扭曲）是 P4+ 的增强选项——能做像素级折射扭曲，
  但引入 D3D 依赖与交换链管理，复杂度高，现阶段性价比低。"不用重计算"的
  优化空间主要在：降低捕获频率（静止检测）、只模糊不重采样、把透镜位移
  预计算成查找表——均已列入 §10.4。

### 10.4 修复计划（下一轮 T-049 执行，本轮零代码改动）

1. **采样坐标修**：`_tick` 的 rect 改全局物理坐标（删除 screen-local 平移）；
   回归：副屏 B/C 对比图一致。
2. **自排除修（拖影根因）**：优先 **SetWindowDisplayAffinity 瞬时切换**
   （GDI 捕获前置位、后复位；先 spike 验证"非分层窗 + GDI + affinity"
   的排除有效性与两次调用的开销）；备选 = 窗口强制微透明分层
   （setWindowOpacity(0.9999)，GDI 永久排除；评估对渲染路径的影响）。
   验收 = 连续两次捕获 diff：选中框移动后残影在一个刷新周期内消失。
3. **性能巡检指标固化**：主线程单帧重绘耗时、worker 队列深度、采样→上屏
   延迟纳入 harness 常规检查。
4. **模块化重构（独立小步）**：dock_strip 拆出玻璃/光效绘制模块
   （ui/glass_paint.py，纯函数式：参数进 → 绘制命令出）；散落参数收编到
   theme.Texture/Skin；paintEvent 加防御性 try/except + 计数
   （D-046 qFatal 教训的制度化）。
